# M3 slice: Outputs

**Date:** 2026-10-30. **Covers:** FR-S6 (multiple outputs, windows, displays, slices, masks, grid and Bezier warp, soft edges, test patterns; 10-bit/HDR noted below), the "2 outputs with slices/warp/blend" part of AC1. **Architecture:** decision A54 (outputs are `cmp.window` nodes), `../M3.md`. User page: `docs/outputs.md`.

## What was built

| Item | Where | Notes |
|---|---|---|
| Output mapping | `crates/lsr-gpu/src/output/` (`mod.rs` model, text and tessellation; `pass.rs` GPU) | `OutputMap` of up to 16 `Slice`s: source rect, destination rect or control grid (2–16 per axis), warp `bilinear` / `perspective` (2×2 corner pin, Heckbert homography) / `catmull_rom` / `bezier` (bicubic patches, 3n+1 points), soft edges per side with power and gamma (Bourke's curve, `blend_weight`), polygon mask (≤ 32 points, even-odd, invert), optional image mask, `subdiv`. Text format parsed and written canonically (defaults omitted, one control-point row per line, ≤ 4 decimals). The mesh is tessellated on the CPU only when the text changes and uploaded once; the frame records one render pass (premultiplied over, later slices on top) and writes the uniform block only when it changed. Test patterns (grid, 75% bars, gradient, circles with the slice number from a 3×5 digit font) are drawn per slice in the fragment shader |
| `cmp.window` | `crates/lsr-ops-cmp/src/window.rs`, `lib.rs` (`register`, new `library`) | IMG inputs `in`, `mask`; params `enabled`, `title`, `display`, `fullscreen`, `position`, `window_size`, `width`/`height` (0 = project), `pattern`, `slices` (multiline text). Output size = width × height. Status `2 slices · 1280×720`. Capability: none. Budget 150 µs. CMP's `library` is now registered in the app and the CLI |
| Offline class | `crates/lsr-cli/src/render.rs`, `docs/render.md` | **Pure**, not Sink: the cook is a function of the input and parameters and has no side effect; the native window is the app's. So `render --node <window>` and `check --gpu` produce exactly the mapped image, and the operator is not a `sink` (the app requests open windows itself) |
| App: windows | `crates/lsr-app/src/outputs.rs`; `app.rs` (+20 lines: tab, library, wiring), `stage.rs` (`cook_frame` takes the output nodes) | One egui **deferred** viewport per enabled Window: title, position, inner size, borderless fullscreen on `display` (egui 0.37 `ViewportBuilder::with_monitor`), image stretched over the window, RGB only. Repainted when something cooked. Closing a window sets its `enabled` off (undoable). Enabled windows (and the one the tab shows) are cooked every frame with the viewed node and the Stage deck |
| App: Outputs tab | same file | Pick an output; Window, Fullscreen, Display, Pattern, Resolution, **Match display** (the window's monitor size × native pixels per point). Slices: add, remove, source rect, warp (switching resamples the grid so the shape is kept: 2×2 for perspective, 3n+1 for Bezier), grid size, soft edges, mask (new, clear, invert), Reset warp. Preview of the mapped image with every slice's grid; drag the selected slice's control points (or mask points with Edit mask; click adds, right-click removes). Every change rewrites `slices` canonically through `edit_coalesced` (one undo step per gesture) |
| Example | `examples/two-outputs.lasair` | One composition (ramp, noise on an LFO, a sun) to `left` and `right` windows, 1280×720 each. Each shows 55% of the image (10% overlap) as two slices; soft edges of 0.1818 over the overlap; `left`'s lower slice is a perspective corner pin, `right`'s lower slice a 3×3 Catmull-Rom warp with a mask cutting a corner. Opens two 640×360 windows |
| Docs | `docs/outputs.md` (user page), `docs/operators/cmp/window.md` (generated), `examples/README.md` row |

## Evidence (Apple M5 Pro, Metal, 2026-10-30)

- `cargo test -p lsr-gpu --lib output` (7): empty text = identity, canonical round trip, errors name their line, every warp passes through its corners, the perspective centre is the diagonals' crossing, an even grid is the identity for bilinear, Catmull-Rom and Bezier (4 and 7), blend curve values (0.125 / 0.5 / 0.875 at power 2, two ramps sum to 1 at gamma 2.2), tessellation sizes.
- `cargo test -p lsr-gpu --test output_map` (8 GPU pixel tests): identity map = copy (≤ 1 per channel), a slice lands on its destination quad, a perspective pin follows the homography (quadrant colours at H(u, v), including next to the centre), soft-edge ramp matches `blend_weight` across 256 pixels (±2) and gamma 2.2 lifts the middle, polygon mask and invert, image mask, later slices over earlier, test patterns (bar values, gradient, grid and circles deterministic and opaque, slices differ), steady draws keep one bind group and two target views.
- `cargo test -p lsr-ops-cmp` (1 + 5): schema/help/budget/implementation; through the engine: identity passes the input through at the project size and the output takes its own resolution, slices and soft edges reach the image, a bad description is a node error naming the line until fixed, test patterns replace the input, steady state creates no textures and allocates 23.3 per cook against 18.0 for a one-pass Level (bound 1.5 × one-pass + 2; the extra is wgpu tracking the vertex and index buffers).
- `cargo test -p lsr-app outputs` (2): warp switches keep valid grids and canonical text, regridding keeps the shape.
- `cargo test -p lsr-cli two_renders_of_each_output_are_identical`, plus `every_operator_is_classified`, `examples_are_valid_and_canonical`.
- `cargo run -p lsr-cli --release -- render examples/two-outputs.lasair --node left|right --out .scratch/o1|o2/<node> --range 0-30`: `diff -rq .scratch/o1 .scratch/o2` reports nothing (60 frames per run); frames 0 and 29 differ. Frames inspected: corner pin, Catmull-Rom bulge, masked corner and the soft edge over the overlap all visible.
- `cargo run -p lsr-cli -- check --gpu examples/*.lasair`: 46 ok, `two-outputs` 8 nodes.
- App smoke: `lasair-app examples/two-outputs.lasair --smoke 1500` with `screencapture -x` 4 s in: both windows ("Left projector", "Right projector") open beside the main window showing the mapped images; the Outputs tab (temporarily put in front for one smoke screenshot) shows the settings, slice controls and the preview with the grid handles. 1500 frames in about 12.7 s.

## Not done / follow-ups

- **10-bit/HDR (FR-S6 "where supported")**: not available. eframe 0.37 creates every window's surface with one format chosen by `egui_wgpu::preferred_framebuffer_format` (Rgba8Unorm/Bgra8Unorm first), and the engine renders `Rgba8Unorm`. A 10-bit path needs output windows with their own `wgpu::Surface` (Rgb10a2Unorm or Rgba16Float with an extended-range colour space where the display offers it) outside egui's painter, and a higher-precision engine format for the mapped image.
- **Intermittent stall with output windows open (macOS):** in long smoke runs the app occasionally stopped repainting (main thread idle in the event loop, 0% CPU, smoke's own repaint requests not delivered): seen in 2 of about 6 runs with immediate viewports and 1 of 13 with deferred viewports (the shipped version), never in 4 baseline runs of `stage-deck` without windows. Not diagnosed further; it looks like an eframe/winit multi-window redraw issue on macOS (for example a redraw requested for an occluded window). Needs a check on Windows and a longer soak before AC1.
- **Display names**: egui does not list monitors, so displays are an index; an out-of-range index is ignored by winit (logged). Display size is known only once a window is on that display.
- Outputs update at the app's frame rate (the cook runs in the main window's frame).
- Per-slice colour correction, per-output brightness/black level and saving/loading output presets are not built.

## Open questions for Mark

1. **`slices` as one multiline text parameter** (chosen) rather than per-slice vector parameters: slices vary in number and grid size, which a fixed parameter list cannot express without dozens of parameters per slice; text keeps a dragged point a one-line diff and round-trips canonically. The cost: slice settings cannot be bound to channels or set by live values one at a time (only the whole text). Acceptable?
2. **Offline class Pure, not Sink.** A Window renders its mapped image offline instead of passing its input through. OK?
3. **`enabled` is turned off when the user closes a window** (an undo step). Alternative: closing only hides it for the session and leaves the project unchanged.
4. **Blend gamma default 2.2** (physically right for projectors, so two ramps sum to constant light); 1.0 would make a plain linear-looking ramp.
