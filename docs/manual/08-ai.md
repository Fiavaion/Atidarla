# 8. AI

Atidarla can run AI models inside a patch: picture diffusion, depth and pose estimation,
speech to text and language models. This chapter explains how that works and how to stay in
control of it.

## The ideas

- **AI runs outside the app.** Models run in a separate program, the **AI Host**. If a model is
  slow or crashes, the picture and the rest of the show carry on.
- **AI is asynchronous.** An AI node sends a frame to a host and shows the answer when it comes
  back. The **Output Governor** keeps the node's output moving at the project's frame rate in
  between (below).
- **Models are never bundled.** You download each model with its licence shown to you first.
- **Your data stays home by default.** **Sovereign mode** is on for new projects and blocks every
  connection to the internet.

AI nodes need the AI Host set up once ([chapter 1](01-install.md#optional-extras)):

```sh
cd ai-host && uv sync --extra diffusion --extra vision
```

With an installed Atidarla you do not need another Python for this: add `--python` and the
app's bundled interpreter (`/Applications/Atidarla.app/Contents/Resources/python/bin/python3` on
macOS, `"C:\Program Files\Atidarla\python\python.exe"` on Windows), as
[`docs/install.md`](../install.md) shows.

Without any extras the host has only two built-in test models (`builtin.invert` and
`builtin.echo`). The AI Host protocol is documented in
[`docs/ai-host-protocol.md`](../ai-host-protocol.md) for people who want the detail.

## AI Hosts

Open **View, AI Hosts**. The window lists the hosts the project can use, whether each is ready,
its hardware, the adapters it offers and how often it has restarted. Hosts start (or connect)
when an AI node first needs one.

A node's **Route** parameter says where it runs, in order of preference, for example
`local -> lan:studio -> cloud:runpod`.

- `local`: a host on this computer, started for you.
- `lan:<name>`: another computer on your network running the AI Host. Use **Add a host** in the
  window with its name, address and token.
- `cloud:<name>`: a rented machine or hosted service (below).

A LAN host needs a token. Run it with:

```sh
atd-ai-host --listen 0.0.0.0:7420 --token <secret>
```

Tokens are stored on your computer in a per-user file, never in the project. A node moves to the
next host on its route if its host is not ready, or if the **Latency Budget** is exceeded for 3
seconds.

## Models and licences

Open **View, Models**. Each model shows a coloured badge, and the badge always carries words
too:

| Badge | Meaning |
|---|---|
| **COMMERCIAL-SAFE** | A permissive licence (MIT, Apache, BSD) |
| **RESTRICTED** | Commercial use only under conditions, such as the Stability AI Community Licence |
| **NON-COMMERCIAL** | Research or personal use only |

For each model you can **Read licence**, **Accept licence**, **Download** (or Resume), **Verify**
(checks every file's fingerprint) and **Remove**. **Every** model needs your explicit acceptance
before it downloads. A project can switch on **commercial-safe only** to hide the others.

Models are kept in a per-user folder: `~/Library/Caches/Atidarla/models` on macOS,
`%LOCALAPPDATA%\Atidarla\models` on Windows. They are never put in a project or a show bundle.

The same from the command line:

```sh
atidarla models list
atidarla models accept sd-turbo
atidarla models download sd-turbo --allow-internet
atidarla models verify sd-turbo
atidarla models path
```

Because Sovereign mode blocks the internet, a download needs **Download once anyway** in the app
or `--allow-internet` on the command line. It lifts the block for that one download only.

Today's catalogue ([`docs/models.md`](../models.md)): `sd-turbo` and `sdxl-turbo` (diffusion),
`taesd` and `taesdxl` (tiny picture decoders), `depth-anything-v2-small` (depth), `birefnet-lite`
(segmentation and background removal), `dwpose` (pose), `raft` (optical flow), `swin2sr-x4`
(upscaling) and `whisper-base` and `whisper-small` (speech to text).

## Diffusion

[**Diffusion**](../operators/ai/diffusion.md) restyles its input picture live with a diffusion
model. It blends up to four prompts with weights. You can bind a weight to a signal or to the
Stage crossfader to morph between prompts. Other important parameters: Strength (how far the
result departs from the input), Seed (change it on a beat for a new look), Steps, and the
Governor policy. It needs the model `sd-turbo` from the Models window.

**Hardware.** Real-time local diffusion is a Windows capability with an NVIDIA GPU. Elsewhere
the node routes to a LAN or cloud host on its route, or runs here at interactive rates.

[**Control Prep**](../operators/ai/control_prep.md) turns a picture into an edge map, line art or
similar to steer diffusion.

[**Prompt Clip**](../operators/ai/prompt.md) is an AI clip for the Stage. Wire it into a layer
slot. A Diffusion node whose **Prompts From** names the deck's Mixer takes its prompt, seed and
LoRA from the clips playing on the crossfader's two sides. The learn quest
[An AI clip on the deck](../../learn/quests/06-ai-clip.toml) takes about 20 minutes and uses the
built-in test model if you have not downloaded SD-Turbo.

Example: [`ai-live`](../../examples/ai-live.atidarla/).

## Vision nodes

These run ONNX models on an AI Host and use the best backend there (Core ML, CUDA, TensorRT,
DirectML or CPU):

[Depth](../operators/ai/depth.md), [Segment](../operators/ai/segment.md),
[Background Remove](../operators/ai/background.md), [Pose](../operators/ai/pose.md),
[Optical Flow](../operators/ai/optical_flow.md), [Upscale](../operators/ai/upscale.md), and
[ONNX Inference](../operators/ai/onnx.md) for a model of your choice. They need the host's
`vision` extra and the matching model from the Models window.
[AI Model](../operators/ai/model.md) runs any model a host offers, by adapter and model id.

[**Video Model**](../operators/ai/video_model.md) restyles live video with a streaming
video-to-video model, on a local 24 GB+ NVIDIA host, a LAN host or a cloud provider.

## The Output Governor

AI answers arrive at their own pace, often slower than the show's frame rate. The **Governor**
fills the gaps. Each AI node has a **Governor** parameter:

| Policy | The output between results |
|---|---|
| `hold` | The newest result stays |
| `blend` | Cross-fades from the previous result to the newest |
| `flow` | Interpolates along the motion between them |
| `passthrough` | Shows the input with a simple effect when no result is fresh |

The render thread never waits for a model. The picture keeps its frame rate whatever the
host does.

## ComfyUI workflows as nodes

If you already use ComfyUI, a workflow can become a node. **Atidarla does not include, install
or start ComfyUI.** You run your own server, on this computer or on your network, and Atidarla
talks to it.

1. In ComfyUI save the workflow with **Workflow, Export (API)**. (The normal Save is the wrong
   format.)
2. In Atidarla choose **File, Import ComfyUI Workflow...** (it reads from `127.0.0.1:8188`), or
   run `atidarla comfy import my-workflow.json --project show.atidarla [--server host:port]`.
3. The workflow appears as an operator `comfy.<name>`. Its settings (seed, steps, prompts)
   become parameters; its image inputs become IMG inputs. Press **run**, or turn on **auto_run**
   to run whenever something changes.

A workflow node works even when the server is off: it opens, and its status line says it cannot
reach the server. To show only the controls that matter, retitle the workflow's nodes in ComfyUI
to start with `atd:`. Full guide: [`docs/comfy.md`](../comfy.md). The Learn quest
[A ComfyUI workflow as a node](../../learn/quests/10-comfyui.toml) takes about 12 minutes.
Example: [`comfy-invert`](../../examples/comfy-invert.atidarla/).

Limits today: one image out per workflow; video, batches and sending results to the media bin
are not done yet.

## Cloud and Sovereign mode

**Sovereign mode** is a per-project switch, on by default. While it is on, Atidarla refuses to
connect to anything on the internet *before a packet is sent*: cloud hosts are skipped,
downloads are refused, and the cloud language-model providers are refused. A badge in the menu
bar shows **SOVEREIGN** or **CLOUD ALLOWED**. Turning it off asks you to confirm and shows your
spending cap.

Things on your own computer or local network still work in Sovereign mode: local hosts, LAN
hosts, a ComfyUI server on your network, Ollama.

When you do allow the cloud, you stay in charge of cost:

- The **spend meter** in the AI Hosts window counts what cloud hosts have charged this session.
- Set a **spend cap**. The router stops using cloud hosts when the cap is reached. A cap of $0
  allows no cloud spending at all.
- Keys are yours. They come from the environment or a per-user secrets file, never from a
  project.

Two cloud targets are built in ([`docs/cloud.md`](../cloud.md)):

- **Your own pod on Runpod** running the AI Host container:
  `atidarla cloud runpod up`, `status` and `down`. A running pod bills by the hour until you
  stop it.
- **Hosted real-time video-to-video** through a local AI Host with a cloud backend, used
  from the Video Model node. You need your own API key.

Some parts of the cloud path have not been checked against live services yet. `docs/cloud.md`
lists them.

## Speech to Text and LLM Chat

These two nodes let a performer talk to the show. They use **DAT wires** (text).

- [**Speech to Text**](../operators/ai/stt.md) transcribes a microphone with Whisper. It listens
  for speech by sound level. When the speaker pauses, it sends what was said and the transcript
  arrives on its `text` output. Use the `level` channel to set the **Threshold** between the
  room and the voice. It needs the host's `stt` extra and the `whisper-base` or `whisper-small`
  model.
- [**LLM Chat**](../operators/ai/llm_chat.md) sends a prompt to a language model and puts the
  reply on its `reply` output. By default it uses Ollama on your computer
  (`qwen2.5-coder:7b`), so Sovereign mode stays on. It can also use an OpenAI-compatible
  server on your network, or Anthropic with your own key and Sovereign mode off.

A typical chain: Audio In, then Speech to Text, then LLM Chat (the transcript goes to its
`prompt` input). The reply comes out of LLM Chat's `reply` output. Put a
[Prompt Template](../operators/dat/prompt_template.md) between the two to wrap each transcript
in a longer prompt. Example: [`speech-chat`](../../examples/speech-chat.atidarla/).
